# Modern Classical Chinese (19th–20th c.) — Project Plan

Draft v0.2 · 2026-11-06

## Goal

A web course for Cambridge students and staff to learn to read 19th–20th century
literary Chinese (late-Qing and Republican 文言 / 淺文言) for their own research.
Explanations are in English, and no knowledge of modern Chinese is assumed.

## Approach

**Content first, app second.** The course is planned and written as Markdown files,
following strict conventions so a web app can later read and render them without
rewriting. The Markdown files remain the single source of truth for content after the app exists.

## Agreed requirements

| Area | Decision |
|---|---|
| Learners | Beginner and intermediate; mostly non-native; English explanations; no reliance on modern-Chinese comparisons |
| Text types | Broad: official, journalistic, essays, letters, scholarly, legal/diplomatic, etc. |
| Display | **Modern layout** = traditional characters, horizontal, punctuated (default). Later units introduce unpunctuated and vertical right-to-left text. No simplified characters |
| Pinyin | Available on glosses, hidden by default |
| Core activity | Graded reading passages; a separate reading-assistant unit for intermediate learners |
| Navigation | Recommended path, but any unit can be opened directly |
| User data | No accounts, no progress tracking on the server |
| Content | Generated by us and reviewed, based on public-domain sources; native-speaker expert review before release |
| AI | Local model in development; large Ollama cloud model for testing and release, called from the server |
| Hosting | Dynamic site (Django, Python) on a Language Centre server |
| Devices | Desktop, laptop, tablet, phone. Online only |
| Timeline | In use from the start of academic year 2027–28; testing and evaluation well before that |

## Notes

- **Rights**: UK law has "fair dealing", not "fair use". Most authors from this period
  are out of copyright anyway, but each passage records its source and rights status.
- **Display variants from one text**: each passage stores one canonical punctuated
  text. The app derives the unpunctuated and vertical versions automatically. Where a
  passage's original punctuation or layout matters, it can be stored separately.

## Content structure

> Now defined in [docs/content-spec.md](docs/content-spec.md), with templates in
> [templates/](templates/). The sketch below is superseded: exercises now sit inside
> passage files, and the glossary is generated.

```
content/
  course.md                 # overview, recommended unit order
  units/
    01-<slug>/
      unit.md               # introduction, objectives, grammar covered
      p01-<slug>.md         # graded reading passage
      p02-<slug>.md
      exercises.md
  grammar/
    <topic>.md              # one grammar point per file, linked from passages
  glossary.md               # cumulative course glossary
  assistant/                # reading-assistant unit (intermediate)
```

Each file has YAML frontmatter (id, title, level, grammar points, source, rights,
review status) and a fixed set of headed sections. Sketch of a passage file:

```markdown
---
id: u01-p01
title: …
level: beginner
grammar: [zhi-possessive, ye-final]
source: …
rights: public domain
status: draft          # draft → reviewed → expert-reviewed
---

## Text
…passage in traditional characters, punctuated…

## Glosses
- 學者 | xuézhě | scholar; one who studies

## Translation
…

## Notes
…
```

The exact syntax still needs settling, e.g. how to gloss a word that appears more
than once with different meanings, and how to write exercises in a form the app can
make interactive.

## Phases

Each phase ends with something you can review.

### Phase 0 — Content conventions
- A short format spec: folder layout, frontmatter fields, section names, gloss and exercise syntax.
- Template files for unit, passage, grammar point and exercise.
- A small validation script (Python) that checks files against the spec.

### Phase 1 — Curriculum outline
> Agreed: [docs/curriculum-outline.md](docs/curriculum-outline.md); skeleton in `content/`
> (status `planned`). *Phase 0 done: spec, templates and validator (`tools/validate.py`).*
> Still to do: check the candidate sources against actual editions.

- Unit sequence from beginner to intermediate: grammar progression, genres,
  and when unpunctuated and vertical text are introduced.
- Candidate public-domain source texts for each unit, with rights recorded.

### Phase 2 — Pilot unit
- One complete unit written to the spec, to test the format and the teaching approach.
- Revise the spec based on what we learn.

### Phase 3 — Content production
- Units written in batches; each batch reviewed by us before the next.

### Phase 4 — Web app (Django)
> Planned in [docs/app-plan.md](docs/app-plan.md): decisions, architecture and milestones M1–M6.

- Renders the Markdown content: course map, passage reader with glosses,
  pinyin toggle, punctuation and vertical-text toggles, grammar links, exercises.
- Reading-assistant unit: Django calls the Ollama model server-side, so the API key stays off the browser.
  Planned in [docs/assistant-plan.md](docs/assistant-plan.md).
- Should start by roughly **February 2027** to leave time for piloting.

### Phase 5 — Testing and evaluation
- Accessibility (WCAG 2.2 AA), testing on a range of devices and browsers.
- Pilot with a small group of learners (target: spring 2027).
- Native-speaker expert review of all content (target: summer 2027).

### Phase 6 — Release
- Deployment to the Language Centre server, documentation, handover.

## Deferred

- Branding / visual identity
